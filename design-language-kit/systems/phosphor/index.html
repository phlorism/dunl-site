PHOSPHOR

● signal locked type: mono-only elevation: none motion: steps() only
← systems

A design language built on CRT physics. The screen is an emitter, not a surface: hierarchy comes from phosphor intensity, depth comes from brightness, and motion means the system is doing something. Named for P1 phosphor – the green coating that made terminals glow.

Use it for: developer tools, dashboards, status pages, takeover states, and anything that should feel like machinery rather than furniture.

00Principles
Light is emission, not reflection.A CRT emits; it doesn't catch light. There are no drop shadows, no glass, no elevation. Depth is brightness. Layering is intensity.
Aberration is a state, not a decoration.RGB split appears only when something is happening: loading, erroring, taking over. At rest the interface is perfectly calm. If everything glitches, nothing does.
Brightness is hierarchy.One hue, four intensities. 100% for what matters now, 62% for reading, 38% for structure, 16% for residue. No grays. Ever.
Motion is signal, easing is a lie.CRTs don't ease. Every animation uses steps() – state changes snap between frames like a refresh. If it needs a curve, it doesn't belong here.
The mono set is the icon set.● ▲ ✕ ▮ ▸ ▖ do the work of an icon library. If a glyph doesn't exist in the type family, the interface doesn't need it.
01Color

One emissive hue at four intensities, two aberration channels reserved for state, two signal colors for warning and fault. That's the whole palette – nine values, no neutrals. Words never dip below phosphor/62 – the 4.5:1 emission floor; 38 and under is structure.

03Surface & frame

Containers don't use full borders – they use corner ticks, like an oscilloscope reticle. A frame marks where attention goes without boxing content in. Fills stay under 8% intensity.

frame / standard

Corner ticks at phosphor/100, fill at phosphor/8. The primary container for grouped content and live modules.

frame / dim

Ticks at 45%, no fill. For reference material, specimens, and anything at rest.

takeover – the glitch overlay

Full-screen interruptions – errors, lockouts, dramatic reveals – use the Glitch overlay. This is the one moment aberration runs free: static, scanlines, RGB split. Dependency-free, themeable, respects reduced motion.

api: Glitch.show(text | options) · Glitch.error(code, message) · Glitch.hide() · esc or click dismisses

05Motion

CRTs don't ease. Every animation runs on steps() — state changes snap between frames like a refresh, and the step count is the fidelity dial: 2 for a blink, 3 for a state, 12 for a sweep. If something moves smoothly here, it's lying about what it is.

No cubic-bezier. No spring. No opacity fades on text — words are output, and output arrives whole. prefers-reduced-motion collapses everything to instant state changes and hides the static layer entirely.

06Voice

The system speaks in log lines: lowercase, present tense, timestamped when it matters. It states, it doesn't apologize. "uplink lost. retrying in 8s." – never "Oops! Something went wrong."

07Do / Don't

Do

  • Use brightness for hierarchy – four intensities of one hue
  • Reserve aberration for loading, error, and takeover states
  • Use corner ticks instead of full borders
  • Set all numerals tabular; align data right
  • Write system messages as log lines
  • Collapse all motion under reduced-motion

    • Don't

  • No drop shadows, glass, or gradients – light is emission
  • No border-radius above 2px
  • No easing curves – steps() or nothing
  • No second typeface, no grays, no emoji
  • No aberration at rest – calm until the system acts
  • No more than one signal color per view
  • No words below phosphor/62 – dimmer is structure, not signal
